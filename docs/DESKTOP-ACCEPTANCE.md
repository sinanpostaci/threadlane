# Desktop Acceptance Tooling and Boundaries

This document describes the reproducible desktop acceptance harness for Threadlane across two complementary layers:

1. **Browser interaction and geometry acceptance** (`Playwright` against the compiled production frontend bundle with test-injected Tauri IPC fixtures).
2. **Native Linux Wayland + StatusNotifier tray acceptance** (`NixOS` VM running `sway`, `waybar`, and the packaged `threadlane` + `threadlane-desktop` binaries).

> **Integration status boundary:** Adding this acceptance harness in an isolated task worktree does **not** mean production workspace UI integration is complete. Where `apps/desktop/src/app.tsx` has not yet been combined with the full workspace UI implementation, the Playwright contract assertions in `apps/desktop/tests/workspace.spec.ts` intentionally fail closed instead of falling back to mock pages or fake pass states.

## 2. Reproducible Dependencies and Lockfile Rules

- `apps/desktop/package.json` defines `"test:browser": "playwright test --config playwright.config.ts"` alongside the locked frontend dependencies in `apps/desktop/package-lock.json`.
- On NixOS, dynamically linked browser binaries downloaded by `npm` cannot execute directly; `nix/packages.nix` therefore builds `threadlane-desktop-playwright` by combining:
  - `desktopNpmModules` (built offline from `apps/desktop/package-lock.json` via `desktopNpmDepsHash`),
  - `pkgs.playwright-test`, and
  - `pkgs.playwright-driver.browsers` (pinned reproducibly in `flake.lock`).
- At runtime, `threadlane-desktop-playwright` invokes `scripts/desktop-acceptance.py --prepare-playwright-stage` to validate `THREADLANE_ACCEPTANCE_ARTIFACT_DIR` against the same `.local` pre-existence + `git check-ignore` or dedicated external directory rules and allocate an always-fresh `0700` owned child directory (`staging-desktop-*`, or an explicit non-preexisting child path under `THREADLANE_ACCEPTANCE_ARTIFACT_DIR`). Preexisting or outside `THREADLANE_ACCEPTANCE_STAGING_DIR` overrides are rejected, no recursive deletion (`rm -rf`) is ever performed, and Node's ESM resolver locates `@playwright/test` and `vite` cleanly without writing `node_modules`, `.vite`, or `dist` into the Git worktree.
- **Lockfile hash rule:** Whenever npm dependencies in `apps/desktop/package.json` and `apps/desktop/package-lock.json` change, recompute `desktopNpmDepsHash` in `nix/packages.nix` against the committed `apps/desktop/package-lock.json` so `desktopFrontend` and `desktopNpmModules` stay bit-for-bit reproducible.

## 3. What Each Stage Verifies

### 3.1 Browser Acceptance (`apps/desktop/tests/workspace.spec.ts`)

Opens the compiled production `index.html` bundle over loopback HTTP (never a standalone `design.html` mockup and never screenshot-only comparison):

1. **Honest no-IPC boundary & tray route:**
   - Opening `/` without injected `__TAURI_INTERNALS__` renders an honest unavailable/disconnected state without fabricating sample chats.
   - Opening `/?surface=tray` mounts the `360x320` compact tray surface without horizontal overflow and dispatches `desktop_tray_action` (`show_main`, `hide` on `Escape`, `quit`).
2. **Responsive geometry & focus management (`1040x760`, `761x760` vs `760x760`, `360x500`):**
   - Wide `1040x760`: inline sidebar width (`220px..320px`) and titlebar sidebar collapse/expand button (`<= 72px` collapsed rail).
   - Exact `760px` drawer boundary: `761x760` keeps inline sidebar without drawer button; `760x760` switches to compact navigation drawer trigger, moves focus inside the modal dialog on open, and dismisses + restores focus to the titlebar trigger on `Escape`.
   - Narrow minimum `360x500`: `Messages`, `Jobs`, and `Activity` tabs, drawer dialog, and content panels fit within `360px` with zero horizontal overflow (`scrollWidth <= innerWidth`).
3. **Chat-first tabs, per-chat `Active`/`Archive`, scroll preservation, and spinner alignment:**
   - `Messages` is selected by default and separated from `Jobs` and `Activity`.
   - `Active` / `Archive` filters and per-chat `Archive` / `Restore` persist under `localStorage['threadlane.desktop.workspace.chatArchive.v1']` keyed strictly by canonical four-part `WorkspaceChatIdentity` (`wchat:v1:...`), ignoring forged `job_id` or title keys.
   - Appending a message while anchored at the bottom keeps the viewport at the bottom; appending while scrolled up preserves `scrollTop` and anchor bounding-box `y` within `<= 4px`, reveals the `new-events` jump control, and jumps to the latest message when clicked.
   - `Activity` renders `.tl-spin` only on active `running` rows (vertically centered within `<= 3.5px` of its status container) and omits spinners on completed Worker or local MCP rows.
4. **Semantic workspace contract fixtures (`apps/desktop/tests/fixtures/workspace.ts`):**
   - **Live Coworker vs Worker separation:** Coworker `waiting_for_input` + configured `gpt-5.4` (`counts_as_runtime_telemetry: false`) remains distinct from concurrent `running` Worker telemetry (`gemini-4-argon-high`).
   - **Stale and Disconnected native samples:** `regenerateWorkspaceSnapshotAt` advances `generated_at_ms` without resetting `observed_at_ms` / `last_success_at_ms`; durable `Messages` and `Jobs` remain readable.
   - **Wrong chat scope isolation:** Sibling chats sharing `canonical_project_scope` and unaligned records missing `binding_id` never leak across `Messages`, `Jobs`, or `Activity`; `desktop_open_codex_chat` receives the active chat's verified `source_id` and `thread_uuid`.
   - **Superseded historical failure vs active attention:** Retry-recovered attempt 1 failure remains inspectable in job history without masquerading as active human approval attention.
   - **Pending acceptance vs verified acceptance:** Completed Worker candidates without Closure acceptance (`pending_review`) are never labeled `Accepted` / `Verified accepted`.

### 3.2 NixOS VM Native Wayland + Tray Acceptance (`nix/desktop-acceptance.nix`)

Runs inside an isolated QEMU NixOS VM with `services.seatd`, `services.dbus`, `sway` (`WLR_BACKENDS=headless`, `WLR_LIBINPUT_NO_DEVICES=1`, `WLR_RENDERER=pixman`, `xwayland disable`, `focus_follows_mouse yes`, solid `#2e6f40` compositor background via `swaybg`), `threadlane-persistent-wayland-input`, and `waybar` (`org.kde.StatusNotifierWatcher`):

- **Persistent guest `seat0` `pointer|keyboard` (`capabilities == 3`) prerequisite:** A bare headless Sway compositor with `WLR_LIBINPUT_NO_DEVICES=1` starts with `wl_seat` `capabilities == 0` and zero input devices, so compositor seat cursor commands alone do not deliver real Wayland pointer/keyboard seat capabilities to GTK/WebKit clients. Before `waybar` or `threadlane-desktop` launches, `PersistentGuestInputFixture` starts the owned `threadlane-persistent-wayland-input` helper (compiled via `wayland-scanner` from `${pkgs.wlrctl.src}/protocol/wlr-virtual-pointer-unstable-v1.xml` and `virtual-keyboard-unstable-v1.xml`), binds `zwlr_virtual_pointer_manager_v1`, `zwp_virtual_keyboard_manager_v1`, and exact `wl_seat` `"seat0"`, attaches a valid compiled XKB v1 keymap (`WL_KEYBOARD_KEYMAP_FORMAT_XKB_V1`) with **zero setup keypresses**, unconditionally flushes and roundtrips device/keymap creation even if capabilities already existed, and retains both virtual devices continuously across all 14 checks (including `wtype -k Escape` and `Quit`) until finite owned scene cleanup. Readiness uses `stdin=DEVNULL` + bounded `select` timeout and finite `SIGTERM` -> bounded `wait` -> owned `SIGKILL` fallback; `verify_seat0_input_state` fails closed unless `seat0` has `capabilities == 3` and a valid `seat0.devices` membership list whose `(type, identifier, name)` entries match `swaymsg -t get_inputs -r` (rejecting missing/non-list `seat0.devices`, foreign-seat devices, and cross-seat ambiguity with zero fallback to other seats) both before launch and after `Quit`. Host displays (`/run/user/*`, `DISPLAY`) are strictly rejected.
- **Isolated VM software-WebKit rendering configuration:** In the software-rendered guest VM session only, `client_env` sets `WEBKIT_DISABLE_COMPOSITING_MODE=1` alongside `WLR_RENDERER=pixman`, `WEBKIT_DISABLE_DMABUF_RENDERER=1`, and `LIBGL_ALWAYS_SOFTWARE=1`. This setting is never exported to host, global NixOS, or product launcher environments.
- **No broad or forced tray compositor rules:** Sway configuration contains **no** `for_window [all] floating enable`, **no** `app_id` floating match, and **no** tray floating/size/position rules (preventing Sway from masking an oversized tiled tray surface). Only exact `for_window [title="^Threadlane$"] floating enable` (with no compositor `resize` or `move` directive) is present for the `main` window.
- **Unforced `main` default geometry, explicit responsive resize, and bounded painted-content readiness:** Verifies `threadlane` CLI availability on `PATH` alongside `threadlane-desktop --no-codex-startup-setup`, native Wayland `xdg_shell` protocol on `main`, and the application's unforced default `1040x760` `main` size (`initial_default_main_rect`) **before** executing explicit `swaymsg [con_id=...]` responsive test resizes to `360x500` (`explicit_resized_min_main_rect`) and back to `1040x760` (`explicit_resized_wide_main_rect`). Bare mapped `sway get_tree` nodes or unpainted solid fallback rectangles are rejected: before accepting `01-main-default-1040x760.png`, `02-main-explicit-resize-360x500.png`, and `02b-main-restored-wide-1040x760.png`, `evaluate_main_window_paint_readiness` waits boundedly (never sleep-only and without frontend mocks/injection) for both native `get_tree` dimensions and rendered `grim` workspace pixel diff bounds + interior painted foreground contrast across `titlebar`, `navigation`, and `workspace_body`, and both report validators (`scripts/desktop-acceptance.py` and `nix/desktop-acceptance.nix`) require and validate all three stages (`default_1040x760`, `resized_360x500`, `restored_wide_1040x760`). Sway `get_tree` geometry is valid for `main` only and is never used to qualify the tray popup.
- **Dual HiDPI/standard outputs & verified global cursor input:** Configures `HEADLESS-1` (`1920x1080` @ `scale 1.0`) and `HEADLESS-2` (`2560x1440` physical / `1280x720` logical @ `scale 2.0`), verifies `StatusNotifierItem` registration on session D-Bus, locates rendered tray icon pixels in `waybar` via `grim`, and positions/clicks the pointer via `swaymsg -r seat seat0 cursor set/press/release` (global layout coordinates, asserting JSON `[{"success": true}]` on every command rather than relative `cursor move` or direct D-Bus `Activate`).
- **Rendered pixel geometry for `zwlr_layer_shell_v1` / native tray popups:** Temporarily hides `main` via its real close-to-tray path (`CloseBehavior::HideToTray`), confirms zero visible normal windows and uniform `#2e6f40` solid background below the `waybar` panel strip on both outputs, opens the popup via the real StatusNotifier icon, captures before/after output screenshots (`grim` + Pillow, excluding the panel strip), and measures the actual rendered popup rectangle in physical pixels. Converts using real output origin and scale (`1.0` and `2.0`), asserting compact `360x320` logical dimensions (within `±4px` raster rounding tolerance only — `~720x640` physical at `scale 2.0` and `~360x320` physical at `scale 1.0`), dense interior/footer paint, target output bounds containment, proximity to the clicked tray icon, and strict output ownership (`0` changed workspace pixels on the non-clicked monitor). Legitimate GTK3 `zwlr_layer_shell_v1` overlays (which need not appear in Sway `get_tree`) are measured directly from rendered pixels without app-supplied test telemetry or hardcoded flags.
- **Pointer-transit dwell survival across multiple UI refreshes (`focus_follows_mouse yes`), outside-click, and immediate `Escape`:** Opens via the StatusNotifier icon on `HEADLESS-2` (`scale 2.0`), moves the Wayland pointer **without clicking** across 5 waypoints from the panel strip into the measured popup interior, and dwells for at least `9.5s` (`MIN_POINTER_DWELL_MS = 9500ms`, spanning at least two `4000ms` periodic UI refresh cycles plus margin in addition to the `180ms` blur grace), measuring actual monotonic elapsed time and immediately re-evaluating rendered `grim`/Pillow popup bounds, fill density, and `HEADLESS-1` cross-output cleanliness (`other_output_diff_pixels == 0`). Clicks outside measured bounds and verifies rendered disappearance without app exit. Reopens on `HEADLESS-1` (`scale 1.0`) and sends `Escape` (`wtype -k Escape`) **before any interior click**, verifying rendered disappearance while the persistent `seat0` devices remain attached.
- **Sustained reopen refresh-paint survival, measured-bounds `Open Threadlane` restore, `Quit`, Codex non-mutation, independent per-owner cleanup, and bounded failure captures:** Reopens the popup on `HEADLESS-1` (`scale 1.0`) after `Escape` dismissal, verifies initial rendered paint and `HEADLESS-2` cross-output cleanliness, and **before** clicking `Open Threadlane`, captures `10` bounded fresh pixel measurements targeting `1s` intervals (`0.90s..2.5s` actual measured inter-capture time including screenshot/analysis overhead; never exceeding `2.5s` per step) across a `>= 9.0s` monotonic sampling window via `evaluate_rendered_popup_capture` (capturing both `HEADLESS-1` and `HEADLESS-2` on every sample with zero retry loop masking blank frames, requiring compact `360x320` logical bounds, dense interior/footer paint, `fill_ratio >= 0.70`, consistent `changed_pixels`, and measured `other_output_diff_pixels == 0`). Embeds the mandatory `refresh_paint_survival` proof (`headless2_scale2_dwell` and `headless1_scale1_reopen` with monotonic timestamps and intervals) directly in `vm-acceptance-report.json` (and writes `refresh-paint-survival.json` in the VM artifact directory), then clicks `Open Threadlane` using coordinates derived from measured popup bounds to restore `main` and hide the popup; reopens on clean `HEADLESS-2` while `main` remains open and clicks `Quit` using measured popup bounds, asserting clean exit code `0`, preserved `seat0` device identities, and confirming `$HOME/.codex` was never created. Owned scene processes (`threadlane_desktop`, `waybar`, `persistent_input`, `sway`) and log handles are shut down independently with bounded `SIGTERM`/`SIGKILL`/`wait` (`cleanup_owned_scene_processes`) strictly by owned handle: a post-kill `wait` timeout or signal error on one owner never aborts cleanup of remaining owners or masks an earlier scene failure, and if cleanup fails after scene checks succeeded, `complete_owned_scene_and_write_passed_report` writes `"status": "failed"` and refuses `"passed"` qualification. On any failure, `record_owned_scene_failure` / `collect_bounded_failure_diagnostics` captures bounded screenshots of both outputs (`HEADLESS-1`, `HEADLESS-2`), bounded Sway JSON (`outputs`, `seats`, `inputs`, `tree`), and redacted bounded tails (`<= 16 KiB`) of owned VM process logs (`sway.log`, `waybar.log`, `persistent-input.log`, `threadlane-desktop.log`) before stopping Sway, without masking the original exception or reading any private user runtime path. Test-driver artifact extraction retains compatibility across both `copy_from_vm` and `copy_from_machine`. All check booleans start as `False` and flip `True` only after their assertions pass.

## 4. Isolation, Artifact Routing, and Host Safety Rules

`scripts/desktop-acceptance.py` enforces the following non-negotiable host protections:

1. **Child-only environment & D-Bus isolation:**
   - Every test child process receives fresh `0700` directories for `HOME`, `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, and `XDG_RUNTIME_DIR` inside `<run_dir>/isolation`, wrapped in `dbus-run-session --`.
   - `DBUS_SESSION_BUS_ADDRESS`, `CODEX_HOME`, and non-whitelisted host environment variables/credentials are stripped from child environments; the runner's own parent `os.environ` is never mutated.
2. **Host Codex and host session non-interference:**
   - `build_desktop_launch_argv` and the NixOS VM harness unconditionally pass `--no-codex-startup-setup` to `threadlane-desktop`.
   - Host-mutating commands (`nrs`, `nixos-rebuild`, `systemctl`, `pkill`, `killall`, `shutdown`, `reboot`) are blocked in `assert_command_allowed`. The harness never modifies host `~/.codex`, never stops running host Threadlane/Codex sessions, and never invokes `nrs`.
3. **Artifact directory gate:**
   - Logs, Vite build/cache outputs, Playwright staging trees, JSON/HTML reports, failure traces/screenshots/videos, and copied VM artifacts go **only** to:
     - `<repo>/.local/desktop-acceptance` **if and only if** `<repo>/.local` already exists as a non-symlink directory and `git check-ignore` confirms both `.local` and the target path are ignored, **or**
     - an explicit external `--artifact-dir /abs/path` outside Git worktrees.
   - `threadlane-desktop-playwright` delegates staging preparation to `scripts/desktop-acceptance.py --prepare-playwright-stage`, never bypassing artifact validation and never recursively deleting caller-controlled paths; all preexisting directories, files, and symlinks are preserved.
   - `git status --porcelain=v1 --untracked-files=all` is compared before and after execution; any unexpected tracked or untracked checkout mutation fails the run.
4. **Fail-closed verification and browser sandboxing:**
   - `apps/desktop/playwright.config.ts` unconditionally sets `use.launchOptions.chromiumSandbox = true` (while preserving optional `THREADLANE_CHROMIUM_EXECUTABLE` path overrides) with no `--no-sandbox` or skip fallback.
   - Zero discovered Playwright tests, any skipped Playwright test, any failed assertion, suite-level config/syntax errors, any missing/false check in `REQUIRED_VM_CHECKS` (`no_forced_tray_compositor_rules`, `rendered_popup_geometry`, `pointer_transit_dwell_survival`, etc.), or any violated VM structured invariant (`grim_pixel_diff` `360x320` rendered bounds at scales `1.0` and `2.0`, `main_window_paint_readiness` across `default_1040x760` / `resized_360x500` / `restored_wide_1040x760`, mandatory `refresh_paint_survival` across `>= 9.5s` `2x` pointer-transit dwell and `10` bounded `1s`-target (`0.90s..2.5s` actual inter-capture interval) `1x` reopen captures over `>= 9.0s` with measured `other_output_diff_pixels == 0` and finite non-boolean numeric/monotonic guards, `scene_cleanup.ok == True` across all owned scene processes, `focus_follows_mouse == "yes"`, `cursor_positioning_command == "set"`, no-click pointer transit dwell `>= 9500ms`, `Escape` dismissal without prior interior click) fails with exit code `1` in both `scripts/desktop-acceptance.py:verify_vm_acceptance_report` and the outer NixOS VM test driver.
   - Running a single stage (`--stage browser` or `--stage vm`) emits `"full_desktop_acceptance": false` (`"status": "partial_browser_passed"` or `"partial_vm_passed"`). Passing `--require-full-acceptance` requires `--stage all` and fails closed unless both browser and NixOS VM stages execute and pass.

## 5. Commands

```bash
# 1. Run offline unit tests for isolation, artifact gates, and fail-closed parsers
python3 -m unittest scripts/test_desktop_acceptance.py

# 2. Prepare a private git-ignored .local directory (if using default in-repo artifact routing)
mkdir -p -m 0700 .local

# 3. Validate isolation plan and git-ignore gates without launching browsers or VMs
python3 scripts/desktop-acceptance.py --dry-run

# 4. Run only the Playwright browser stage during iterative UI integration
#    (records "full_desktop_acceptance": false)
python3 scripts/desktop-acceptance.py --stage browser

# 5. Run only the NixOS Wayland + StatusNotifier tray VM stage
#    (records "full_desktop_acceptance": false)
python3 scripts/desktop-acceptance.py --stage vm

# 6. Run full desktop acceptance (both browser + NixOS Wayland/tray VM required)
python3 scripts/desktop-acceptance.py --stage all --require-full-acceptance

# 7. Alternatively, route all artifacts to a dedicated directory outside the repository
python3 scripts/desktop-acceptance.py \
  --artifact-dir /tmp/threadlane-desktop-acceptance \
  --stage all \
  --require-full-acceptance
```

## 6. Acceptance Boundaries, Provenance, and Unsupported Cases

- **Source inspection and offline harness unit tests are NOT final real VM acceptance:** Passing `scripts/test_desktop_acceptance.py` or `scripts/desktop-acceptance.py --dry-run` only validates runner isolation, non-destructive staging, persistent-input/paint-readiness helper logic, and fail-closed report verification. Real native Wayland and tray acceptance is only established by building and executing the actual NixOS QEMU VM test (`--stage all --require-full-acceptance`) against the integrated `threadlane` and `threadlane-desktop` binaries.
- **Provenance of input-capability evidence vs pending outside-click qualification:** In isolated Wayland diagnostics, a bare headless Sway compositor (`wl_seat` `capabilities == 0`) lacks delivered pointer/keyboard input; adding a persistent virtual pointer (`capabilities == 1`) enables real `waybar` `StatusNotifierItem.Activate`, `2x` `360x320` popup geometry, and pointer-transit/dwell checks, while `click_outside_dismiss` still observed `nativeFocus=false` when no persistent keyboard device existed before app launch. Qualification of `click_outside_dismiss` and the full 14-check sequence under persistent `pointer|keyboard` (`capabilities == 3`, valid XKB v1 keymap, zero setup keypresses) remains **pending** actual VM execution; this fixture update does **not** claim that outside-click passes or that zero product defects remain.
- **Main-window-only responsive floating is NOT tray qualification:** Using `for_window [title="^Threadlane$"] floating enable` (without forced size) and explicit `swaymsg [con_id=...]` resizes applies exclusively to `main` window default/responsive checks (`1040x760` vs `360x500`). It does not float, resize, or qualify the tray popup; the tray popup has zero compositor rules and must render compact `360x320` logical bounds on its own (`zwlr_layer_shell_v1` overlay) as proven by `grim`/Pillow output pixel diffs.
- **Browser tests alone are never full desktop acceptance:** `--stage browser` validates DOM, CSS geometry, keyboard focus, scroll anchoring, localStorage lifecycle persistence, and contract projection, but cannot substitute for `--stage vm` native Wayland windowing and StatusNotifier tray verification.
- **Unsupported environments and untested platforms:** `nix/desktop-acceptance.nix` targets native Linux Wayland (`sway` + `waybar` `org.kde.StatusNotifierWatcher`) with `zwlr_virtual_pointer_manager_v1`, `zwp_virtual_keyboard_manager_v1`, and `seat0` `capabilities == 3`. Compositors lacking those virtual-input protocols or `seat0` `pointer|keyboard` capabilities fail closed during fixture setup. X11/Xwayland (`xwayland disable`), bars without `StatusNotifierWatcher`, macOS `NSStatusItem`, and Windows notification-area shells are not covered by this VM suite.
- **Sustained mixed-scale refresh blanking vs short single-pass checks (pending WebKitGTK backport verification):** A short tray check can finish before periodic `4000ms` UI refreshes fire, whereas holding and reopening the tray popup across `2x` and `1x` outputs exposed blank reopen frames correlating with sparse `13x13` CPU damage updates in software WebKitGTK (upstream fix [`WebKit/WebKit@bfae1a7`](https://github.com/WebKit/WebKit/commit/bfae1a7), packaged separately without relaxing `WLR_RENDERER=pixman`, `WEBKIT_DISABLE_DMABUF_RENDERER=1`, `WEBKIT_DISABLE_COMPOSITING_MODE=1`, or `LIBGL_ALWAYS_SOFTWARE=1`). The strengthened `>= 9.5s` `HEADLESS-2` dwell and `10`-sample `1s`-interval `HEADLESS-1` reopen sequence (`>= 9.0s` window) immediately reject any blank, `13x13`, low-fill, wrong-scale, or cross-output-leaking frame without retry masking. Live NixOS VM execution against the patched WebKitGTK package remains **pending** parent verification; this update makes **no** claim that native VM acceptance has passed.
- **No production UI or unexecuted VM completion claim in this package:** Harness updates and offline unit tests do not claim that `apps/desktop/tests/workspace.spec.ts` or `desktop-acceptance-vm` have passed until both stages actually execute and pass in full validation.
