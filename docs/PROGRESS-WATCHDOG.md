# Advisory progress supervision

The progress watchdog moves a soft deadline only within the invocation's existing
hard runtime ceiling. Supported write, edit, and explicit check tool categories
are advisory advancement hints. They do not prove that a file changed, a check
passed, or a task was accepted. Provider prose, read-only tools, and generic
command labels do not extend the deadline. A legitimate research task can raise
attention while continuing to run. Attention never cancels, retries, changes a
model, or grants more execution scope.

At the soft deadline, uncertain progress produces at most one software-generated
`SupervisorAttention` event. It contains fixed reasons, counters, and monotonic
times, with no provider instructions, prompts, paths, or credentials. Provider
JSON cannot mint that typed event. The supervisor mapper checks its software
marker, reserved line number, bounded strict DTO, and consistent attention state.

The durable core snapshot stores the first validated attention separately from
ordinary latest-event text. Later provider activity cannot overwrite it. It
survives event coalescing, completion, and database reopen. Its presence is
advisory evidence at the recorded elapsed time, not a claim that execution is
currently stuck. Missing attention is not proof of healthy progress: the live
observer channel is bounded and nonblocking.

Original approved host Coder invocations expose this snapshot through their
real worker progress in `approved_task` and controller task observations returned
by `execution_status`. Advisory Architect, Orchestrator, Reviewer, Closure, and
direct derived correction calls do not currently forward a live observer to the
approved host worker ledger. Their final execution reports may contain watchdog
state, but this package does not claim during-call native progress notifications
for those routes. AGY provider-health notices use a separate cumulative diagnostic
channel on these routes; they do not extend tool-progress coverage. In particular, absent file writes during read-only planning do
not prove a stuck planning role.

Existing hard runtime limits and process cleanup remain unchanged. Cancellation,
output overflow, uncertain-effect reconciliation, approval and review acceptance,
and publication permissions retain their separate boundaries. Exact remote
inference termination, token-cap enforcement, costs, cross-platform qualification,
and physical power-loss guarantees are not established by these fixtures.

For the original host Coder route, each verified invocation can reserve one
progress-attention wakeup under its own fingerprint, shared with the existing
16-attempt per-job notice cap. New progress notices stop once 14 total attempts
exist, preserving the final two shared slots for later fatal or terminal notices.
Existing fingerprints still deduplicate before this progress subcap is checked.
Changing a job revision or reopening an owner does not replay it. Intent and uncertain delivery remain durable and are reconciled,
never blindly retried. The wake text contains only the fixed job-status prompt;
Coworker reads `execution_status` for evidence. Delivery submission does not prove
that the human read the notice.

Owner teardown failures are recorded and eligible for a bounded fatal-error
notice while the verified physical guard remains held, before its release.
Status inputs are validated before release. A new error or concurrent change
observed only after ownership has been released returns an error without a new
owner-authorized wakeup; this package does not claim authority beyond that
boundary.


## Separate provider diagnostic hints

[Provider health](PROVIDER-HEALTH.md) reports bounded AGY log-text pattern matches
as `unverified_provider_diagnostic_hint`. An invocation-owned private FIFO does
not authenticate the semantics of a record. A matching forgery remains unverified
and changes no authoritative lifecycle, approval, hold, failure or execution state.
This channel does not wait for the watchdog soft deadline and does not move it.

Health uses a cumulative watch observer, preserving first/last observations and
retry counts through coalescing independently of ordinary progress delivery.
Original approved host Workers use authenticated host snapshots; owned planning,
Reviewer, Closure and derived correction calls use verified invocation records.
The native outbox is outside the pipe reader; native delivery and supervised
provider polling run concurrently on those scoped calls.

One early fixed diagnostic-availability wakeup per invocation follows durable
scope/owner-checked persistence. Health joins progress/failure attention in the
14-of-16 subquota; planning applies the same two-slot terminal/fatal reserve.
A hint is historical after recovery, terminal observation or owner loss; it does
not erase real failure, immutable observations or Unknown receipt reconciliation.
Native Coworker reads the named status once and explains unverified AGY text,
counts, elapsed time and availability in the human conversation language (Turkish
in this pilot) without guessing root cause.

These changes do not fix every missing live tool-progress route. AGY 1.5.3 startup
capture qualification, source Linux fixtures and installed/live-provider/macOS
acceptance are distinct. Unavailable or truncated diagnostics never imply health.
